# Fun Toolkit UI

## 三分钟快速开始

这是可离线使用的团队工具页 Skill。先复用随包模板与资源，再按用户的输入、输出和业务流程调整；不要另造一套相似但不同的 UI。

### 新手教程

1. **安装完整目录**：将 ZIP 内容解压到名为 `fun-toolkit-ui` 的文件夹，按客户端支持方式添加整个目录。Codex 项目级路径及更新方式见 [团队接入](references/team-setup.md)。确认 Agent 已读到本文件；仅打开网页或下载 ZIP 不代表安装完成。
2. **检查附件**：运行 `python3 scripts/check_package.py`；在 Windows 可用 `py -3`。预期身份、资源、引用和清单一致；脚本只读，不联网。
3. **搭起页面**：对新独立工具运行 `python3 scripts/create_tool.py /实际工作目录/cover-tool`。目标必须不存在；得到带中英、五态和最新反馈资源的页面。修改现有网站时按其框架接入，不覆盖全站样式或业务代码。
4. **接真实业务并验收**：把模板中明确标注的演示任务换成真实读取、处理和下载。按 [验收清单](references/acceptance.md) 检查桌面和手机，交付可打开的预览、实际输出及未测边界。

### 首次使用示例

把 [活动封面任务](references/first-task.md) 交给 Agent：

```text
使用 $fun-toolkit-ui 创建一个独立的「活动封面」工具。
上传 PNG、JPG、WebP，在本地居中裁成 512×512，支持修改文件名，真实生成并下载 WebP。
复用随包模板、空状态、加载动画和弹窗；保留中英文与移动端适配。
补齐无效文件、处理中防重和参数变化后的旧结果处理。不要接生产统计，不要发布。
```

预期是实际可操作的页面及 512×512 WebP，不是模拟成功截图。示例任务与验收条件随包提供，[真实试做截图](examples/event-cover-trial.webp) 和执行边界见 [验证范围](references/validation.md)。

## 解决什么问题

让同事创建的工具保持同一套页面结构、颜色、字体、表单和状态语言，并把“按规范做”落实为可复用的代码与可检查的结果。在线参考为 [Fun Toolkit 设计规范](https://fun-toolkit.pangweishen1.workers.dev/design-system/)，本包固定资源快照，离线使用不依赖网页。

## 适用与不适用场景

用于 Fun Toolkit 的图片、文件、批量和动画选帧工具，以及既有工具的 UI 调整。纯后端、单独修业务算法、无关品牌重设计不因出现“工具”二字强行套用本 Skill。保留用户明确选择的技术栈和产品要求；不要为了使用模板重写现有应用。

## 需要准备什么输入

从任务和仓库取得：输入类型与限制、自动或手动生成、参数与默认值、输出尺寸/格式/质量/命名、错误恢复和统计要求。缺信息时先做不依赖它的部分，只补问影响结果的关键项。已有页面先读其规则、共享组件、路由和实际任务流程。

按需读取：基础视觉与控件见 [视觉及表单](references/foundations.md)，布局和业务接入见 [工具页框架](references/tool-page-framework.md)，空态与动效见 [反馈规范](references/feedback-states.md)，改原站三工具时再读 [生产适配边界](references/production-integration.md)。

## 完整操作步骤

按真实流程组织页面，优先采用现有组件与原生能力。

1. 确定单文件多规格、批量或动画选帧变体；保持全站页头、左对齐标题与灰色帮助、工作区、输出区、简洁页脚。参数放在相关预览旁，删掉任务不需要的模块。
2. 从 `assets/tool-page-starter/` 复用样式变量、按钮、表单、弹窗、8 张反馈 SVG 与 `feedback-motion.css/js`。作用域和字体间距以随包规范为准；不使用黑色主按钮 Hover，不叠加粗焦点线。
3. 用真实任务状态驱动 empty / loading / ready / processing / success / error；模板的五态演示仅用于看样式。处理中立即防重并设置 busy，未知进度用 Spinner；错误和结果不能等待动画才出现。
4. 接真实读取、校验、处理、编码、下载；处理成功再提交新结果。对会改变输出的参数建立结果失效规则；预览背景、语言和视口变化不改变文件像素。失败保留可恢复输入，是否保留上一份可用结果按业务说明。
5. 使用轻动效；普通内容 180ms 入场、120ms 退场，Canvas/裁切区域只做不移位的淡入。Spinner 800ms、Skeleton 1600ms；弹窗 260ms 轻弹性、7px 玻璃模糊。视差只给装饰，触屏/减动静态，离屏/后台暂停视觉循环。
6. 标签、错误、空态、帮助和可访问名称一并做中英；手机单列，操作区至少 44px，输入字号 16px，保留键盘焦点。先验证真实上传、生成与下载，再核对文件、移动布局与状态恢复。
7. 接入原站的新工具同时补首页、导航、路由与语言。独立工具不必连接原站服务；只有用户要求接共享统计时再补前后端登记，成功输出文件数与有效下载动作分开计，失败和纯预览不计，ZIP 不重复计生成。

## 输出示例和可下载文件

交付可运行源码、所用资源及版本、实际输出文件、桌面/手机预览和简短验收结果。模板通过复制脚本生成；目录中保留全部相对资源，不能只交 `index.html`。浏览器无法预览或下载时明确未验证部分，不用构建通过代替效果结论。

本包还带 `assets/production-adapter/` 的现网适配层快照，供修改原站时对照；它绑定原站三个工具的 DOM，不是新工具自动注册器。没有 Python 时，可完整复制模板目录，按清单手动核对。

## 常见失败及处理方式

仅复制主文件会丢插图和样式，应保留整个模板目录。处理中无限转圈先查实际任务的完成/失败收尾；比例或格式错误查导出画布和编码，不改预览背景冒充修复。换语言丢文件、旧任务覆盖新输入、参数改后下载旧结果，均需修任务状态而非加动画。原站统计只登记三个工具，新工具不能直接使用任意工具名发送事件。
