设计与开发共用

轻量、清晰、好用。

让每个运营工具都拥有同一种使用体验。以现有 Fun Toolkit 为基础，统一视觉尺度、控件行为与完整状态，方便团队扩展新的工具。

房间背景头像框Banner规范示例 · 新增状态尚未在正式站实现
提取现有风格保留浅灰页面、白色圆角卡、蓝色主操作、绿色替换、简洁导航与原有品牌标识。尺寸基于当前源码的最终样式层级。
补充可执行标准表单描边、错误语义色、完整状态、键盘行为等属于新增统一规范。本目录是组件示例，不代表这些状态已全部上线。

一个工具，一条主线

上传 → 预览 / 调整 → 生成 → 下载。每个区域只有一个最突出的主操作。

状态可见，反馈明确

可操作、处理中、已完成、失败都能被识别。用文字与图标共同表达，不依赖颜色。

桌面紧凑，手机好点

保留工作台密度；手机提供至少 44 × 44 px 的操作区域，避免横向滚动。

04 / ACTIONS & STATES

按钮与状态

蓝色负责生成、导出和上传；绿色只用于替换；灰色承载使用说明等低优先级操作。一个区域避免多个同等强度主按钮。

扩展完整状态

动作层级

主操作 44 px；工具栏紧凑 36 px；小操作 32 px。手机点击区域统一至少 44 px。

危险动作是新增场景规范：文字描述结果，需要不可逆确认时再弹窗；不能借用绿色“替换”样式。图标+文字间距 8 px；图标按钮必须有 aria-label 或可见提示。

规则统一做法
字段组成标签 → 输入 → 帮助或错误。必填文字在表单开头说明；可用星号补充，不仅靠颜色。
校验时机首次提交或完成输入后校验；尚未输入时不抢先报错。已出现错误后，在用户修改时及时重新校验。
错误文案说明问题与修复方式，例如“请输入 16–2048 之间的整数”；避免“参数错误”“非法值”。

只读与禁用只读可聚焦与复制；禁用不能编辑且提供原因。两种状态在视觉和语义上明确区分。
长度与数量临近上限或限制明确时显示字数；数字标注单位和范围。字符数含空格，不用像素宽度代替长度约束。
下拉与复杂选择少量且短的选项优先原生 select；互斥用 radio；多选用 checkbox。自定义下拉需额外实现键盘导航与读屏语义。

校验流程

让用户修正问题，而不是重新填一遍。

  1. 用户首次提交时，验证必填和有效范围。
  2. 错误显示在字段下方，并聚焦第一个错误字段。
  3. 保留所有输入；已报错字段在修改后及时更新状态。
  4. 合法后进入处理中，按钮保宽并禁止重复提交。
  5. 成功反馈明确写“演示校验通过”，避免误认为正式提交。

现网需求表单与本例的区别

示例不是后台接口契约。

当前需求表单包含：标题（必填，100 字符）、任务说明（必填，2000 字符）、联系方式（可选，120 字符）。“输出宽度”是本规范为演示数值字段而补充的控件，不表示现网需求表单已经存在此字段。

服务端仍需独立校验与防重复。前端校验只改善反馈，不能替代接口规则。

推荐

“请输入 16–2048 之间的整数。”
指出范围和类型，用户可以直接修正。

避免

“输入错误，请重试。”
没有告诉用户哪个字段或哪里需要调整。

交互与可访问性

桌面、触屏和键盘都能完成同一条操作链路。

  • 按钮允许按内容增长；窄屏英文适当换行，不使用强制截断隐藏关键动作。
  • 手机作者入口可隐藏文字，但保留头像、可访问名和 44 px 点击区。
  • 区块用语义标题；表单标签与输入关联；图标装饰设置 aria-hidden。
  • 加载 / 成功用 role=status 或 aria-live=polite；阻断错误按需使用 alert，不反复播报。
  • 支持 200% 缩放，文字和弹窗不被裁切；键盘顺序与视觉顺序一致。
  • 尊重 prefers-reduced-motion，减少位移与持续动效；操作结果仍然清楚。
  • 操作过程不因窗口宽度、切换背景或语言而丢失用户输入。
标准动效：180 ms；颜色 / 描边 / 阴影优先。避免持续漂浮与不必要的弹跳。

使用边界

交付的是规范，不是自动完成的网站改造。

本目录保留了当前已确认的视觉方向，并为未来扩展提供统一目标。现网仍有历史颜色、圆角、间距与原生字段校验的差异；实施时应有计划地收敛，不能只替换一组 CSS 变量就视为完成。

本文件所有操作均为组件演示，不调用正式接口，不提交需求，不读上传文件内容，不产生真实生成 / 下载统计。

依据：当前源码 index.html、toolkit.css、hub.css、home.css、tokens.css 的只读样式审计。具体实现与上线验收以主交付文档及后续版本为准。版本：2026-10-23 / v1.0。

Banner 使用说明

这是规范中的说明弹窗示例，展示尺寸、文字层级和关闭行为。

  1. 准备图片；使用 GPT 生图时，可在提示词中写明 3.3:1 图片比例。
  2. 上传素材并检查裁切；内容主体留在中心安全区域。
  3. 生成房间 Banner 与游戏 Banner，确认预览后下载。
游戏 Banner 预览可切换黑色与透明；实际导出仍保持透明背景。

键盘提示：Tab 在弹窗内切换，Escape 关闭。关闭后返回刚才的按钮。
